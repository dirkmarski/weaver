# Weaver

A dependency-free static page that generates a fresh sudoku on demand. When the page loads you choose a difficulty (Easy, Medium, Tricky or Hard); only then is a puzzle generated and shown in a 9x9 grid with the 3x3 boxes shaded in two alternating light colours (blue and cream, checkerboard style). Puzzles are generated at run time (never taken from a stored bank) and always have exactly one solution.

## View
Open `index.html` in a browser, or serve the folder:

    python3 -m http.server   # then visit http://localhost:8000

## How to play
- On load, pick **Easy**, **Medium**, **Tricky** or **Hard**. The chosen level is shown above the grid. **New puzzle** clears the grid and returns to the difficulty prompt.
- Bold dark numbers are givens and cannot be changed.
- Click an empty cell and type a digit 1-9. Other input (letters other than N, 0, pasted or dropped multi-character text) is rejected and the cell keeps its previous value. With Notes off, Backspace or Delete clears the cell's value; on a cell that holds only notes it does nothing and the notes stay.
- Keyboard: with a cell focused:
  - Arrow keys move to the nearest cell that is not a given in that direction, in the same row or column. Cells holding your own value are valid targets. Givens are skipped and there is no wrapping (at the edge, or with only givens beyond, the focus stays put). Holding an arrow key auto-repeats.
  - Arrow keys never change a value, a note, the Verify results or Notes mode.
  - Press **N** (or `n`) to toggle Notes without leaving the cell; nothing is typed. Holding N toggles once (key auto-repeat is ignored).
  - Ctrl/Cmd/Alt combinations keep their browser behaviour.
- Click **Notes** to switch pencil-mark notes on (`Notes: On`) or off (`Notes: Off`). It starts Off for every puzzle.
  - Notes on, digit 1-9 in an empty cell: adds a small grey note in a fixed spot of a 3x3 mini-grid (1 top-left ... 9 bottom-right); typing it again removes it.
  - Notes on, Backspace or Delete: on an empty cell removes all its notes; on a cell holding your value, clears the value.
  - Notes on, a digit in a cell that already holds your value does nothing.
  - Notes off, a digit in a cell with notes: enters the value and removes its notes.
  - Verify ignores notes (a notes-only cell counts as empty), and changing a note keeps the Verify flags and message.
  - **New puzzle** discards all notes.
- Click **Verify** to check the grid. Checking is by the sudoku rules only (no stored answer is compared), so any valid solution is accepted.
  - Complete grid: tells you whether it is solved.
  - Incomplete grid: tells you whether the numbers so far break any rule. If they do not, it also says how many cells are empty; if they do, it only points out the mistakes.
  - Numbers you entered that repeat a digit in their row, column or 3x3 box are shown in red (both digits if two of yours clash). Givens are never flagged (the orange clash outline does include givens).
- Click **Hint** to learn the **naked single** and the **hidden single**, and, when there is no single, **pointing**. Hint never fills in a cell; you always enter the digit yourself. Hint looks at the givens and the values you entered (notes are ignored) and follows the sudoku rules only.
  - A **naked single** is an empty cell where the numbers already in its row, column and box leave only one digit that fits.
  - A **hidden single** is a digit that has only one possible place in a box, a row or a column, even if that cell also fits other digits. That cell is the only empty cell of the box, row or column where the digit does not already appear in the cell's row, column or box, and the digit is not yet in that box, row or column.
  - Order: Hint teaches the technique you have applied less so far in this puzzle, adding together, for each technique, the "on your own" and "with a hint" numbers on its line in the block below the message. If the counts are equal, which includes the start of a puzzle, it prefers the naked single on Easy and the hidden single on Medium, Tricky and Hard. The level is the one you chose for the current puzzle.
    - Preferring the naked single: if a naked single exists, Hint teaches it, even when a hidden single exists earlier in the grid. Only when there is no naked single does it look for a hidden single.
    - Preferring the hidden single: Hint first looks for a hidden single whose cell is not also a naked single (at least two digits fit that cell). It uses the first such cell in reading order, with the box, row, column and digit order described below. If there is none, it follows the naked-single order above.
    - Both clicks of one hint explain the same cell: nothing that decides the preference changes between them.
  - **Pointing** is a step in a box: a digit that is not yet in the box fits in two or more of its empty cells, and all of those cells are in one row (or one column), so the digit cannot go anywhere else in that row (column), and that can make another cell a single.
    - When: Hint looks for pointing only where it would otherwise say there is nothing to teach: no rule is broken, the grid is not full and there is no naked and no hidden single. Singles are always taught first, and the preference above is not affected. A step must remove the digit from at least one cell of the row (column) outside the box, where the digit fitted until then.
    - Order: boxes in reading order (top-left first), and within a box the digits 1 to 9. The first step that makes at least one cell a single is used; its target is the first cell in reading order that is a single after that step, whichever form it has. The naked form: an empty cell in the row (column) outside the box where exactly two digits fitted, the pointing digit and one other; the cell must be the other digit. The hidden form: in a box, row or column that does not hold the pointing digit (the box is checked first, then the row, then the column), the digit now fits in one empty cell only; that cell must be the pointing digit.
    - First click: the target is highlighted in amber and gets focus; the box and the row (column) are lightly tinted, and in the hidden form so is the unit where the single arises (see below); the target itself stays amber. The message for the naked form is "Hint: try pointing. In the box of rows R1-R2 and columns C1-C2, the digit D fits only in row L, so it cannot go anywhere else in row L. That means D cannot go in row R, column C, and only one other digit fits there now. Click Hint again to see why." For the hidden form it is the same first two sentences followed by "Then look at U: D now has only one place left there. Click Hint again to see why." U is "row N", "column N" or "the box of rows R1-R2 and columns C1-C2" (the box of the target cell). ("column L" instead of "row L", twice, for a column; all these numbers count from 1). The naked-form text tells you the answer is a different digit; the hidden-form text tells you it is the pointing digit itself.
    - Second click: the same highlight and tint stay, and a cell holding the pointing digit (givens and your own values) gets the purple ring and digit only if it shares a row, column or box with at least one "reason cell": an empty cell of the box that is not confined (see below) or, in the hidden form, an empty cell of the unit U (see below) other than the target and the removed cells. Every digit that qualifies is ringed, even when two of them block the same cell; there may be no ring at all. Two more kinds of cell are marked, in both forms: each empty cell of the box where D fits ("confined") gets a dashed purple outline and a small purple D in D's own pencil-note position (1 top-left, 2 top-middle, ... 9 bottom-right), and each empty cell of the row (column) outside the box where D fitted until the step ("removed", the target too in the naked form) gets a small grey D in the same position, struck through by a diagonal line (also on the amber target). So the badge covers only D's own note slot, never another note. These marks are bold, on a white chip, so they differ from the small grey pencil notes. Below the message a smaller, plain "key line" explains the marks: "Key: dashed purple = the only places for D in the box; struck grey D = a D can no longer go there; purple ring = a D that rules out other cells." (the last clause is left out, and the line ends after "go there.", when no cell is ringed). The key line shows only while a pointing explanation is showing; the first click, the singles and every other Hint text have none, and it is removed with the hint. The message is "Pointing: in the box of rows R1-R2 and columns C1-C2, the digit D fits only in row L, so D cannot go in row L outside that box." (when every empty cell of the box is confined, " (the box has no other empty cells)" is inserted right after "fits only in row L") followed by, for the naked form, "Row R, column C could only take D or X, so it must be X." or, for the hidden form, "That leaves row R, column C as the only cell in its U where D fits, so it must be D." (U is box, row or column). Further clicks show the same explanation.
    - Enter the hinted digit in the target cell (Notes off) and the hint goes away and "Well done! You applied pointing: row R, column C is V." is shown (unless that entry fills the last empty cell, see "Filling the grid" below). This entry adds 1 to "Pointing: ... with a hint" in the block below the message and credits the cell (see "Applying a technique on your own" below for the credited-cell rule). A different digit in the target cell, or a digit elsewhere, is judged as usual.
    - On your own: with no hint for that cell showing, an entry that is not a naked or a hidden single (those are recognised first, in that order) counts as pointing on your own if ONE pointing step, as defined above, makes it a single. After that one step, either the entered cell is one of the cells the digit was removed from and only the entered digit is left there (naked form), or the entered digit is the pointing digit and the entered cell is the only empty cell left in its box, row or column (checked in that order) where it fits (hidden form). If several steps qualify, the first in the order above is used (boxes in reading order, then digits 1 to 9). Two or more pointing steps in a row (chained) are not recognised, and neither is an entry with a conflict in the grid before it, in a filled cell or with the digit already in the cell's row, column or box. The message is "Well spotted! You applied pointing on your own: in the box of rows R1-R2 and columns C1-C2, the digit D fits only in row L, so row R, column C is V." ("column L" instead of "row L" for a column; all numbers count from 1, the box is named as in the hint). It adds 1 to "Pointing: ... on your own".
  - First click, naked single: the cell is highlighted in amber, its row, column and box are lightly tinted, focus moves to the cell, and the message tells you to check its row, column and box. If several cells qualify, the first one in reading order (top row first, left to right) is used.
  - First click, hidden single: the cell is highlighted in amber and focus moves to it. Only the one box, row or column where the digit has just one place is lightly tinted (not all three), and the message names it ("in its box", "in its row" or "in its column") and tells you to check where each missing digit can go there. The first cell in reading order that is a hidden single is used (when Hint prefers the hidden single, the first one that is not also a naked single). For that cell the box is checked first, then the row, then the column, and within one of them the digits are checked from 1 to 9.
  - Second click (while that hint is showing): the same highlight and tint stay and the message explains. For a naked single it names the digit that fits and the 8 digits it excludes. For a hidden single it names the digit and says that every other empty cell of that box, row or column already has that digit in its row or column (box), column or box (row), or row or box (column); in addition, a cell holding that digit (givens and your own values) gets a bold purple ring and a purple digit only if it shares a row, column or box with at least one other empty cell of that box, row or column besides the hinted cell, so you can see the digits that rule out the other cells (a digit that rules out nothing there is not ringed; there may be none). There is no key line for a single. The digit is still not entered. Further clicks show the same explanation.
  - Enter the hinted digit in that cell (Notes off) and the highlight (and tint, purple rings and pointing marks) goes away and "Well done! You applied a naked single: ..." or "Well done! You applied a hidden single: ..." is shown (unless that entry fills the last empty cell, see "Filling the grid" below). Any other value change removes the hint (and may show a "Well spotted!" message or a "not counted" message, see below).
  - If some numbers break the rules, Hint names one clash, in the plain style of the other Hint messages (not red, not green): "Row R1, column C1 and row R2, column C2 both hold E in the same U. Change or clear one of them first, then click Hint again." (the named clash, see "Applying a technique on your own" below). If more than two cells clash, " Other numbers break the rules too: click Verify to see which." is added at the end. If every cell is filled, it says so; if there is no naked single, no hidden single and no pointing step that makes a single, it says "No naked single, hidden single or pointing step right now. At this point the puzzle needs another technique." In these cases nothing is highlighted.
  - Applying a technique on your own: with Notes off, enter a digit 1-9 (typed, or pasted or dropped as a single digit) into an editable cell that holds no value (it may hold notes). Only such an entry is judged. Overwriting a value, clearing a value and anything typed with Notes on are never judged. The messages below are replaced by the message from "Filling the grid" below when the entry fills the last empty cell.
    - If that digit is the only digit that fits the cell (it is the only digit that does not appear in the cell's row, column or box), the message is "Well spotted! You found a naked single on your own: row R, column C is D." (R, C and D are the cell's row and column and the digit).
    - Otherwise, if the digit is not yet in the cell's box, row or column and the cell is the only empty cell of it whose row, column and box do not contain the digit, the message is "Well spotted! You found a hidden single in its box on your own: row R, column C is D." (with "row" or "column" instead of "box" when that is the unit). The box is checked first, then the row, then the column, and the first one that qualifies is named.
    - A cell that is both a naked and a hidden single is reported as a naked single.
    - If neither applies and it is not pointing on your own either (see Pointing above), or if the digit clashes, or if some numbers in the grid just before the entry break the rules, nothing is rewarded and nothing is counted, but the entry is not left unanswered. The message says why (unless the entry fills the last empty cell, see "Filling the grid" below), in the plain style of a Hint message (not green, not red), with R, C and D as above:
      - If D is already in the cell's row, column or box (even when the grid before the entry already breaks the rules): "Entered: row R, column C is D. D is already in this cell's U, at row R2, column C2, so it breaks the rules. It is not counted." U is "row", "column" or "box": the first of row, column, box (in that order) that already holds D, and row R2, column C2 is the first cell of that unit in reading order that holds D. This names a rule clash only; the cell is not turned red (red flags appear only after Verify; the clashing cells are outlined in orange, see "Clash outline" below) and the text does not say whether the digit matches the solution.
      - Otherwise, if some numbers in the grid just before the entry break the rules: "Entered: row R, column C is D. D is not in this cell's row, column or box, but row R1, column C1 and row R2, column C2 both hold E in the same U, so it is not counted. Change or clear one of them first. Entries after that count again; this one stays uncounted." If more than two cells clash, " Other numbers break the rules too: click Verify to see which." is added at the end. The entry is not counted later either, and the text does not say whether D matches the solution.
      - The named clash: the grid is the givens plus your values (notes ignored), as for Verify. A cell clashes if its digit also appears in another cell of its row, column or box (givens included; Verify turns only your own values red). P is the first clashing cell in reading order (top row first, left to right) and E its digit. Look in P's row, then its column, then its box: in the first of these that holds E in another cell, Q is the first such other cell in reading order, and U is "row", "column" or "box". The clash is named P first, then Q, with numbers counted from 1. The same named clash is used by the Hint message above.
      - Otherwise (the digit fits but is neither a naked single, a hidden single nor a pointing step there): "Entered: row R, column C is D. It was not a naked single, a hidden single or a pointing step at this point, so it is not counted." It does not say whether the digit matches the solution.
      - None of these messages changes a count or flags a cell red; red flags still appear only after **Verify**. The clash outline (below) is the only live mark.
    - If a hint (first or second click) is showing for that cell and you enter the hint's digit, it counts as done **with a hint** (naked single, hidden single or pointing) and the "Well done!" message above is shown instead (unless that entry fills the last empty cell, see "Filling the grid" below). If you enter a different digit in the hinted cell, or any digit in another cell, the entry is judged as on your own.
  - Below the message, while a puzzle is shown, the heading "Techniques applied in this puzzle" is followed by the line "Naked single: N on your own, M with a hint", a short grey definition of a naked single, the line "Hidden single: N on your own, M with a hint", a short grey definition of a hidden single, the line "Pointing: N on your own, M with a hint" and a short grey definition of pointing. The three lines show on every level, always, starting at 0. The three definitions are `TECHNIQUE_DEFINITIONS.naked` ("Only one digit fits this cell: its row, column and box already hold the other eight.") and `TECHNIQUE_DEFINITIONS.hidden` ("This digit fits in only one cell of a row, column or box, even if that cell could take other digits.") and `TECHNIQUE_DEFINITIONS.pointing` ("In a box, a digit fits only in one row (or column), so it cannot go anywhere else in that row (column); that can leave a single."); they are smaller than the count lines and never change during a puzzle. All six counts start at 0 when you choose a level. Each rewarded entry in a cell not yet counted in this puzzle adds 1 to the matching count; if you clear a counted cell and enter a single (or a pointing step) there again, the message is shown again (unless that entry fills the last empty cell, see "Filling the grid" below) but no count changes (if you enter a digit that is not a single there, the "not counted" message above is shown instead, and no count changes). Counts never go down (clearing or changing a value, Verify, Hint and notes leave them alone). The block is hidden on the difficulty prompt after **New puzzle**, and nothing is stored between page loads.
  - The hint (highlight, tint, purple rings, pointing marks, key line and message) is removed by any change to a value, by **Verify**, by **New puzzle** and by choosing a level. Changing notes keeps it. Clicking Hint also clears any red flags and message before showing its own (never the clash outline).
- Filling the grid: when a change to a value of a cell you can edit leaves that cell holding a digit and every cell of the grid is then filled, the message is shown straight away, without clicking Verify. This applies to a digit typed with Notes off (including one that overwrites a value) and to a single digit pasted or dropped. Notes changes, clearing a value, Verify, Hint, rejected input and arrow keys never trigger it.
  - If the numbers follow the sudoku rules, the message is green: "Puzzle solved! Techniques applied: O on your own, H with a hint." O is the "on your own" counts of Naked single, Hidden single and Pointing added together, and H is the "with a hint" counts of the three, as in the block below the message. The entry that filled the last cell is counted first, so a technique it completes is included. The wording is the same for every O and H, including 0 and 1.
  - If some numbers break the rules, the message is red: "Every cell is filled, but some numbers break the rules. Click Verify to see which." No cell is flagged red by it; red flags still appear only after you click **Verify** (any clashing cells are outlined in orange, see "Clash outline").
  - This message replaces any "Well spotted!", "Well done!" or "not counted" text that the same entry would have shown. A rewarded entry is still counted in the block below the message.
  - Nothing else changes: the grid stays editable, **Verify** and **Hint** work and show the texts described above, and the next change to a value clears the message (if that change fills the grid again, the message is shown again).
- Any change to a value clears the red flags and the message (entering the hinted digit shows "Well done!", a single or a pointing step you find on your own shows "Well spotted!", and a digit entered into an empty cell that is not a single or a pointing step, or that is entered while the grid before the entry already breaks the rules (even if it would be a single), shows the "not counted" message (first the one for a digit already in the cell's row, column or box, else the one naming the clash in the grid, else the not-a-technique one), which does not say whether the digit matches the solution; an entry that fills the grid shows the message from "Filling the grid" instead; overwriting a value, clearing a value and anything typed with Notes on show no new message, except the "No numbers break the rules now" message below). Apart from these messages and the orange clash outline there is no live checking; red flags appear only after Verify.
- Clash outline: after every change to a value (typed, pasted or dropped digit, overwrite, clear; Notes on or off), every cell that clashes (the `findConflicts` cells of the givens plus your values, notes ignored, givens included) gets a dashed orange outline (`clash` class in `style.css`; not red, amber or purple, no fill; it stays visible with the blue focus ring and on the red Verify fill; a clash and a Hint highlight never show together, because Hint marks nothing while a clash exists and any value change removes a showing hint). A cell that no longer clashes loses it. Verify, Hint (both clicks), notes changes, Notes mode and arrow keys neither add nor remove it, and the red Verify flags can show on top of it. **New puzzle** and choosing a level leave no outline. An outlined cell you can edit has ", clashes" at the end of its screen-reader label (after any notes); the suffix goes with the outline.
- Clash fixed: when a change to a value goes from at least one clash to none (only a clear or an overwrite can), the message line shows, in the plain style, "No numbers break the rules now. New entries are counted again." If the same change fills the grid, the "Filling the grid" message is shown instead. The next change to a value, Verify or Hint replaces it.

## Difficulty levels
Each puzzle is a random complete grid with cells removed in random order; a cell stays removed only if the solution remains unique (and, for Easy, Medium and Tricky, still solvable by the level's technique). After removal the puzzle is graded: Medium, Tricky and Hard puzzles that are still solvable by the lower level's technique are discarded and a new puzzle is generated, so each level needs something the one below does not.

| Level  | Givens | Solvable using |
|--------|--------|----------------|
| Easy   | 36-40  | naked singles only (a cell with just one candidate) |
| Medium | 30-35  | naked singles and hidden singles (a digit with only one place in a row, column or box); NOT solvable by naked singles alone |
| Tricky | 27-31  | naked singles, hidden singles and pointing (the step Hint teaches, see Pointing above); NOT solvable by naked + hidden singles alone; entering each hinted digit solves it, Hint never says there is nothing to teach |
| Hard   | 22-29  | exactly one solution; NOT solvable by naked singles, hidden singles and pointing (needs other techniques or guessing) |

Generation typically takes a few milliseconds (Tricky: tens of milliseconds, up to a few hundred). An internal time cap (1000 ms) guarantees click-to-render stays well under 2 seconds; if it were ever hit, the best valid unique puzzle found so far (fewest givens) is returned and the result has `capped: true` (it could then have more givens than the band or be easier than the level). `generatePuzzle` results also report `attempts`.

## Test
Requires Node 18+ (22+ for the page tests; no packages needed):

    node --test            # (on newer Node versions, observed on Node 24, "node --test tests/" is treated as a path and fails)

The tests are targeted: hand-built grids for the behaviour rules (golden path, edge cases, error conditions) and at most 10 seeded generated puzzles per level for the generator properties. The whole run takes about 2 seconds with Chrome (about 0.6 seconds without it, when the page tests are skipped).

The page tests (`tests/page.test.js`) load the real `index.html` in one headless Chrome, with `Math.random` replaced by `seededRng`, press keys and click buttons, and check the DOM (status text and class, tally lines, cell classes). They need Node 22+ (global `WebSocket`) and Google Chrome or Chromium, and use only Node built-ins (no packages). Chrome is looked up in `CHROME_PATH`, then in the usual macOS and Linux locations. Without Chrome the page tests are reported as skipped, with the reason; the other tests still run. To force the skip, set `WEAVER_NO_CHROME=1`; with `CHROME_PATH` set to a missing file they are skipped too, with no other lookup:

    CHROME_PATH=/path/to/chrome node --test
    WEAVER_NO_CHROME=1 node --test     # page tests skipped, unit tests only

Later UI work adds its page checks to `tests/page.test.js`. Chrome and its temporary profile are removed when the run ends, also after a failed test or on Ctrl-C / SIGTERM (not after `kill -9`).

## Files
- `index.html`, `style.css` - page and styling (`td.clash`: the orange clash outline)
- `sudoku.js` - pure logic, exported for Node (and as `window.Sudoku`), plus the browser UI:
  - `generatePuzzle(level, {rng, maxMs})` (level `'easy'`, `'medium'`, `'tricky'` or `'hard'`) -> `{level, puzzle, solution, givens}` (9x9 arrays, 0 = empty); `generateSolution(rng)`; `seededRng(seed)` for reproducible output; `countSolutions(grid, limit)`; `solvableBy(grid, 'naked'|'singles'|'pointing')` (`'pointing'`: singles, and when none is left a `findPointing` step, repeated until the grid is full or no step is left); `LEVELS` (`{min, max, technique, beyond}` per level: the givens band, the technique the puzzle must be solvable by and the one it must not be)
  - `isValidSolution`, `findConflicts`, `clashCells(grid)` (flat indices 9 * r + c, ascending, of the cells to outline: the `findConflicts` cells), `fixedMessage(before, after)` (the "No numbers break the rules now..." text when `before` has a clash and `after` has none, else `''`; the page lets `completionFor` override it), `namedClash(grid)` -> `null` when no rule is broken, else `{phrase, extra}` (the named clash: `phrase` is "row R1, column C1 and row R2, column C2 both hold E in the same U", `extra` is the "Other numbers break the rules too..." sentence when more than two cells clash, else `''`; used by `hintFor` and `creditEntry`), `verify`, `sanitizeDigit`, `buildGrid(puzzle, values)` (grid passed to verify; notes excluded)
  - keyboard: `nextCell(puzzle, r, c, 'up'|'down'|'left'|'right')` -> `[r, c]` of the next editable cell (givens skipped, no wrap) or `null`
  - hints: `findNakedSingle(grid)` -> `{r, c, digit, seen}` (0-based r/c, `seen` = the 8 digits excluded, ascending) or `null`; `findHiddenSingle(grid, options)` -> `{r, c, digit, unit}` (0-based r/c, `unit` is `'box'`, `'row'` or `'column'`) or `null`; `options` is optional and `{notNaked: true}` skips cells that are also naked singles; `preferredTechnique(tally, level)` -> `'naked'` or `'hidden'` (the technique with the lower count of own plus hint entries; on a tie `'naked'` for `'easy'`, else `'hidden'`); `findPointing(grid)` -> the first pointing step that makes a single, `{r, c, digit, form, unit, box, line, index, pointDigit, confined, removed}` or `null` (`confined` and `removed` are ascending flat indices 9 * r + c: the empty cells where D fits in the box and in the line outside it; all other numbers 0-based: `r`/`c` the target cell, `digit` the digit to enter there, `form` `'naked'` or `'hidden'`, `unit` for the hidden form only, `box` 0-8 in reading order, `line` `'row'` or `'column'`, `index` the row or column, `pointDigit` the pointing digit D; it does not check for naked or hidden singles first, `hintFor` does); `hintFor(grid, step, prefer)` (`prefer` is optional: `'hidden'` looks for a hidden single that is not a naked single first and otherwise, like a missing or `'naked'` value, teaches a naked single before a hidden single; with no single, a pointing step is taught) -> `{kind, technique, unit, r, c, digit, text}` (kind `conflict`, `full`, `none`, `nudge` or `explain`; step 2 gives `explain`; `technique` (`'naked'`, `'hidden'` or `'pointing'`) is set for `nudge` and `explain` only; `unit` only for hidden singles and the hidden form of pointing; for `'pointing'` the result also has `form`, `box`, `line`, `index`, `pointDigit`, `confined` and `removed` as in `findPointing`); `hintApplied(hint, value)` -> the "Well done!" text for the hint's technique or `''`; `pointingKey(digit, ringCount)` -> the key line text of a pointing explanation, with the ring clause only when `ringCount` is above 0; `hintMarks(hint, grid)` -> `{area, target, digits, confined, removed}` (flat cell indices 9 * r + c: the tinted cells without the target (for pointing, the box, the line and in the hidden form the hidden unit; on both clicks), the target, and on `explain` the ringed cells, ascending: those holding the marked digit (the hidden single's digit or the pointing digit) that share a unit with a reason cell (a hidden single: the other empty cells of its unit; pointing: the empty box cells that are not confined and, in the hidden form, the empty cells of the hidden unit other than the target and the removed cells); none for a naked single; `confined` and `removed` are the pointing step's cells as in `findPointing`, ascending, on a pointing `explain` only and empty otherwise)
  - rewards: `classifyEntry(grid, r, c, digit)` (grid just before the entry, 0-based r/c) -> `{technique: 'naked'}`, `{technique: 'hidden', unit}`, `{technique: 'pointing', box, line, index, pointDigit}` (0-based, as in `findPointing`; naked first, then hidden, then pointing) or `null`; `emptyTally()` -> `{naked: {own, hint}, hidden: {own, hint}, pointing: {own, hint}}`; `creditEntry(tally, credited, hint, grid, r, c, value)` -> `{tally, credited, text, kind}` (`credited` maps cell index 9 * r + c to `true`; `hint` is the showing `hintFor` result or `null`; inputs are not changed; `text` is the reward, or for a judged entry that earns none the "Entered: ... not counted" text (the digit is already in the cell's row, column or box, which the text names with the cell, else the grid before the entry already breaks the rules, which the text names, else the digit is not a single or a pointing step) with the tally and `credited` unchanged, or `''` when the entry is not judged: the value is `''` or not a digit, or the cell already holds a value; `kind` is `'reward'` for a "Well spotted!" or "Well done!" text, `'notCounted'` for an "Entered: ..." text and `''` when not judged); `statusClass(kind)` -> `'ok'` for `'reward'`, else `''` (the status line's class, so a reward is green and the rest neutral); `tallyLines(tally)` -> the heading and the three tally lines; `TECHNIQUE_DEFINITIONS` -> `{naked, hidden, pointing}`, the plain-language definition shown under each tally line
  - completion: `completionFor(grid, tally)` (grid after the change, tally after `creditEntry`; inputs are not changed) -> `{kind: 'solved', text}` when every cell is filled and nothing breaks the rules, `{kind: 'conflict', text}` when every cell is filled and something does, or `null` while any cell is empty
