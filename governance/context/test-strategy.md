This document outlines the test strategy for the weaver project.

Testing is treated similar to core development. It is carefully planned, pros / cons weighed and maintained over time. It serves a specific purpose and testing is done in a reasonable approach (so for instance, when you want to test something: you include golden path, edge cases, error conditions, mutation testing etc. You don't bruteforce across all values).
Different levels of testing are maintained at different stages:
 - Unit testing or other low level testing
 - User acceptance testing, i.e. executed specifications.
 - Verification and final approval: review of the executed specifications and test summary reports.

The testing needs to ensure the product delivers against the outlined specifications as per specification-strategy.md.
