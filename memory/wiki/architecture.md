## Exports of `sudoku.js` (the `api` object)
- Generation: `generatePuzzle(level, {rng, maxMs})` -> `{level, puzzle, solution, givens, attempts, capped?}`; `generateSolution(rng)`; `seededRng(seed)` (mulberry32); `countSolutions(grid, limit)`; `solvableBy(grid, 'naked'|'singles'|'pointing')` (no claiming: grading is pointing-only); `LEVELS` (`tough` = Tricky's entry, #103).
- Validation: `isValidSolution`, `findConflicts` (all clashing cells, givens included), `verify`, `sanitizeDigit`, `buildGrid(puzzle, values)`.
- Clashes: `namedClash(grid)` -> `null` or `{phrase, extra}`; `clashCells(grid)`; `fixedMessage(before, after)`.
- Navigation: `nextCell(puzzle, r, c, dir)`. Notes: `applyEntry(cell, key, notesMode)`, `noteDigits(mask)`.
- Hints: `findNakedSingle`, `findHiddenSingle(grid, {notNaked})`, `findPointing(grid, {useful})` (does not check singles first; built on internal `pointingSteps` and `singleAfterStep`; `useful: true` skips targets that internal `isSingle(cells, p)` says are already a naked or hidden single), `findClaiming(grid, {useful})` (#102; same result shape as `findPointing`: `box`, `line`/`index` = the line L, `pointDigit`, `confined` in L, `removed` in the box; built on internal `claimingSteps`, rows then columns; both finders share internal `firstTarget(cells, steps, useful, skip)`, and `singleAfterStep(..., skip)` excludes the box as hidden unit for claiming), `preferredTechnique(tally, level)`, `hintFor(grid, step, prefer, level)` (`'tough'`: useful claiming, then useful pointing; `'tricky'` and `'tough'`: useful pointing before singles, #60; claiming last as fallback; internal `claimingHint` builds `technique: 'claiming'` with pointing's shape, so marks, key, reveal and links reuse the pointing render paths), `hintApplied`, `hintKey(hint, hatchedCount, stage)` (key line for a pointing or hidden-single explain; pointing: stage 1 dashed clause only, 2 + struck clause, 3 (default) + the hatched clause only if hatchedCount > 0 (#91); replaced `pointingKey` in #65), internal `aDigit(d)` ("an 8" / "a D", shared by the hidden-single text and the key line), `hintMarks(hint, grid)` -> `{area, target, digits, hatched, confined, removed}`; `hatched` = the reason cells below, ascending, explain only (#65). `ringLink(p, ringed, d)`, `ringRules(q, hatched, d)` (#72, reverse: `{cells, text}`; shares internal `cellPlace`/`sharedUnits`) -> `{partners, text}`: the ringed cells sharing a unit with hatched cell p (reading order) and the link sentence; pure, does not check p is hatched (#68).
  - `digits` (explain only): cells holding D that share a unit with a reason cell. Reason cells: hidden single = the other empty cells of its unit; pointing = empty box cells not confined, plus (hidden form, `hint.unit` set) empty cells of the hidden unit other than the target and the removed cells. None for a naked single. All qualifying rings kept (PM D4).
  - Internal `struckCells(removed)` (#96, generic since #102) names the removed cells for step 2 ("row R, column C", "row N, columns A and B", or per row joined by "; ").
  - Internal `pointingHint(s, step, grid)` adds " (the box has no other empty cells)" on step 2 when every empty box cell is confined.
- Rewards: `classifyEntry` (naked > hidden > pointing > claiming, one step, #104), `emptyTally` (keys naked, hidden, pointing, claiming), `creditEntry(...)` -> `{tally, credited, text, kind}`, `statusClass(kind)`, `tallyLines`, `TECHNIQUE_DEFINITIONS`.
- Completion: `completionFor(grid, tally)` -> solved / conflict / `null`.
- Cell indices in marks and `credited` are flat `9*r + c`; r/c in results are 0-based.

## How index.html wires it
- `sudoku.js` loads at the end of `body`; `render()` finds elements by id and builds the table of `<input>` cells.
- Picker buttons call `choose(level)`; `newPuzzle` resets state. Per-cell `keydown`/`input` handlers call `nextCell`, `applyEntry`, `sanitizeDigit`.
- Value change (`setCell`, the single write path): `before` grid -> `creditEntry`; then `clearResults`, `showClashes(after)`, `fixedMessage`, the credit text, then `completionFor` (wins when the grid is full); `showTally`.
- `clearResults` (Verify, Hint, value changes, `choose`, `newPuzzle`) clears the status, the step-reveal state `steps` and the Next step row (#90), `keyText`, `hatchedRings` and the reserve/invitation (`unlink`), red flags and all hint classes (including `hint-hatched`)/`data-d`; never `td.clash`. Notes changes do not call it, so a hint and its key line survive them.
- `showMarks(marks, stage)` (wiring scope, add-only, #91): stage 1 target/area/confined + `data-d`, 2 + removed, 3 + hatched, rings and `hatchedRings` (so links are inert before 3); sets `keyText` via `hintKey(..., stage)` (shown in the `#link` reserve). Hint calls it with `steps ? 1 : 3` (`steps.marks` keeps the marks), `revealStep` with `steps.shown`.
- Hint button: `hintFor(grid, step, preferredTechnique(tally, currentLevel), currentLevel)`, `clearResults`, `hintMarks`; marks go through `showMarks` (above). The key (`hintKey`) shows on every explain except a naked single; when hatched cells show (stage 3), `hatchedRings = {hatched, rings: marks.digits, d}` (d = pointDigit for pointing, else digit) and `showInvite()` (after the focus call, also in `revealStep`) fills `#key` and calls `scrollIntoView({block: 'nearest'})` once (#97). While `steps` is set, Hint only calls `revealStep` (until step 3) and focuses the target, no redraw (#90); `revealStep` (also the Next step button) focuses the target at step 3. `cellAt(q)` is shared at wiring scope.
- Link (#68, #72): `unlink()` removes `hint-linked`, and `hint-ruled` with its `data-d` (#78), and restores the reserve to `keyText` (class `selected` off) and the invitation (empty when nothing is hatched); `showLink(text)` puts a link sentence in the reserve with class `selected`; `clearResults` calls it. `focusin` on the table calls `unlink()`, then: an entered ring -> `selectRing(p)` (adds `hint-linked` to the ring, `hint-ruled` plus `data-d` to `ringRules(...).cells`, shows its text); a hatched cell -> `hint-linked` on `ringLink(...).partners` and its text. `focusout` -> `unlink`. A document-level `click` handler (runs after the focusout of the cell that lost focus) ignores editable cells (left to focusin, else it would undo a forward link), otherwise unlinks and, on a given ring, calls `selectRing`; it returns early when no hint with hatching shows.
- `relabel(inp)` is the only aria-label builder (position, notes, ", clashes").

## ATDD (#110, it22; rules in process.md "Test strategy applied")
- `specs.test.js` loads every `steps/*.js` (each exports `(define) => {}`, `define(regex, fn)`) and calls `runner.register`: one `node:test` per scenario and per Examples row, read straight from `specs/**/*.feature` (executed, not translated).
- `gherkin.js` parses features; `runner.js` expands Examples, resolves steps and fails on: undefined step, ambiguous step (two regexes match), a placeholder without a column, a parse error, a feature with no scenarios, no feature files. `runner.test.js` self-checks the runner (9 cases).
- Step texts are global across features: a new steps file must not redefine an existing text. Reuse `the message reads "..."` etc. from `steps/own-singles.js`; `steps/hints.js` adds the hint steps.
- Steps hold the assertions; `drivers/game.js` is the only code that loads `sudoku.js` (logic level: `start(rows)`, `enter`, `hintTwice`, `lines`, `linesBeforeLastEntry`; no assertions). "asks for a hint twice" = `hintFor` step 2 = the full explanation (PM D11); there is no page driver yet.
- Known limits (PM D6): an unused Examples column passes silently (PM rule: every column is used); no `|` inside cells.

## Tests
- Run `node --test` from the repo root (on Node 24 `node --test tests/` fails); it runs `tests/` and the specs. 207 tests, about 4 s with Chrome. Specs only: `node --test spec-implementation/specs.test.js`.
- Page tests (#55): one headless Chrome per file; `Math.random` seeded by injecting `seededRng`'s source (regex-extracted from `sudoku.js`, guarded by a seeding assertion); keydown on cell inputs and real button clicks; DOM-only reads; no test hooks in product code. Chrome via `CHROME_PATH` or default macOS/Linux paths; `WEAVER_NO_CHROME=1` or a missing Chrome gives a visible skip with a reason (page evidence must show skipped = 0). Cleanup on normal end, failure, Ctrl-C/SIGTERM and the orphaned test child (EPIPE listeners, ppid watchdog); not after `kill -9`.
- Narrow-width page checks use `Emulation.setDeviceMetricsOverride` (headless Chrome's window has a ~500 px minimum), wait for layout to settle (check the cell width), and clear the override in `finally`.
- Seeds are chosen on purpose: a seeded test guards a rule only if one of its seeds fails under the mutant.
- Which page test pins what (f, f1-f1h, f2, f4, f5, g1): `page-tests.md`. Read it only when adding or changing a page test.
