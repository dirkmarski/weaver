# Architecture

Static site, no dependencies, no build. ADR 002 (in force, it24): from a fresh clone it runs with one documented command, Node 22+ built-ins only (README "## View": `node tools/serve.js`, http://localhost:8000); `specs/running/local-run.feature` guards it. Native ES modules (ADR 001, `governance/context/decisions/001-es-modules.md`, in force), one module per concern; `package.json` is only `{"type":"module"}` (not a build step, PM A1 it23). The page must be served (`node tools/serve.js`, http://localhost:8000); `file://` no longer runs it.

## Modules (ADR 001; README "## Modules" is the authoritative list)
- One concern per root module; `ui.js` is the only module touching the page (DOM, document, window, events); no logic module imports `ui.js`; imports are acyclic; no re-export module (tests and the driver import each function from its owner). Leaves: `board.js`, `texts.js`, `validation.js`, `entry.js`.
- Concerns: board = units, peers, masks, cell naming; validation = grid checks, conflicts; clashes = naming an entry's clash; entry = typing and notes; techniques = singles, pointing, claiming steps; texts = names of cells, boxes, lists in messages; hints = choosing a hint and its texts; hintmarks = cells, key line and links a hint marks; rewards = recognising and crediting own steps; completion = end message; generation = puzzles by level.
- A new root `*.js` is product: add it to README "## Modules" in the same change.
- Guard `tests/modules.test.js`: discovers root `*.js`; exactly one page-touching file (`ui.js`); no logic import of `ui.js`; README list = root `*.js`; acyclic; no re-exports. Known gap (accepted, #117): a `!function(){}()` wrapper is not detected.
- Granularity of "one concern" is not defined by the ADR (PM C2, it23): the README map is the team's reading; a different one is Dirk's call via a new ADR.

## Exports (by module; import from the owning module)
- `generation.js`: `generatePuzzle(level, {rng, maxMs})` -> `{level, puzzle, solution, givens, attempts, capped?}`; `generateSolution(rng)`; `seededRng(seed)` (mulberry32); `countSolutions(grid, limit)`; `solvableBy(grid, 'naked'|'singles'|'pointing')` (no claiming: grading is pointing-only); `LEVELS` (`tough` = Tricky's entry, #103).
- `validation.js`: `isValidSolution`, `findConflicts` (all clashing cells, givens included), `verify`, `buildGrid(puzzle, values)`.
- `entry.js`: `sanitizeDigit`, `nextCell(puzzle, r, c, dir)`, `applyEntry(cell, key, notesMode)`, `noteDigits(mask)`.
- `clashes.js`: `namedClash(grid)` -> `null` or `{phrase, extra}`; `clashCells(grid)`; `fixedMessage(before, after)`.
- `board.js`: `firstHolder`, `cellName(p)` ("row R, column C"; the former duplicate `cellPlace` was removed, #117), `UNIT_NAMES`, `UNITS`, `CELL_UNITS`, `toFlat`, `toGrid`, `usedMask`, `bitCount`, `spotsFor`.
- `texts.js`: `boxName`, `andList`, `struckCells(removed)` (names the removed cells for step 2: "row R, column C", "row N, columns A and B", or per row joined by "; "; #96, generic since #102), `aDigit(d)` ("an 8" / "a D"; hidden-single text and key line).
- `techniques.js`: `findNakedSingle`, `findHiddenSingle(grid, {notNaked})`, `findPointing(grid, {useful})` (does not check singles first; `useful: true` skips targets that internal `isSingle(cells, p)` says are already a naked or hidden single), `findClaiming(grid, {useful})` (#102; same result shape as `findPointing`: `box`, `line`/`index` = the line L, `pointDigit`, `confined` in L, `removed` in the box; rows then columns), `pointingSteps`, `claimingSteps`, `singleAfterStep(..., skip)` (excludes the box as hidden unit for claiming); both finders share internal `firstTarget(cells, steps, useful, skip)`.
- `hints.js`: `preferredTechnique(tally, level)`, `hintFor(grid, step, prefer, level)` (`'tough'`: useful claiming, then useful pointing; `'tricky'` and `'tough'`: useful pointing before singles, #60; claiming last as fallback; internal `claimingHint` builds `technique: 'claiming'` with pointing's shape, so marks, key, reveal and links reuse the pointing paths; internal `pointingHint` adds " (the box has no other empty cells)" on step 2 when every empty box cell is confined), `hintApplied`.
- `hintmarks.js`: `rewardMarks(step, r, c)` (#122; `step` = the own pointing/claiming step, r/c the entered cell) -> `{area, confined, removed, digit, key}`: area = box + line L + (hidden form) the hidden unit; removed = only removed cells in the hidden unit (none in the naked form); key = "Key: amber = the box, rows and columns the message names; dashed purple = the only places for D in the box|row|column[; struck grey D = this step rules D out there].". `hintMarks(hint, grid)` -> `{area, target, digits, hatched, confined, removed}` (`hatched` = the reason cells, ascending, explain only, #65); `hintKey(hint, hatchedCount, stage)` (pointing: stage 1 dashed clause only, 2 + struck clause, 3 (default) + hatched clause only if hatchedCount > 0, #91); `ringLink(p, ringed, d)` -> `{partners, text}` (ringed cells sharing a unit with hatched p, reading order; pure, does not check p is hatched, #68); `ringRules(q, hatched, d)` -> `{cells, text}` (reverse, #72); internal `sharedUnits`.
  - `digits` (explain only): cells holding D that share a unit with a reason cell. Reason cells: hidden single = the other empty cells of its unit; pointing = empty box cells not confined, plus (hidden form, `hint.unit` set) empty cells of the hidden unit other than the target and the removed cells. None for a naked single. All qualifying rings kept (PM D4).
- `rewards.js`: `classifyEntry` (naked > hidden > pointing > claiming, one step, #104), `emptyTally` (keys naked, hidden, pointing, claiming), `creditEntry(...)` -> `{tally, credited, text, kind, marks}` (`marks` = `rewardMarks(...)` for an own pointing or claiming reward, `null` for other rewards incl. hint-credited, absent when not judged or not counted; the gate lives here, #122), `statusClass(kind)`, `tallyLines`, `TECHNIQUE_DEFINITIONS`.
- `completion.js`: `completionFor(grid, tally)` -> solved / conflict / `null`.
- Cell indices in marks and `credited` are flat `9*r + c`; r/c in results are 0-based.

## How ui.js wires the page
- `ui.js` is a module script (deferred); it imports the logic it uses and calls `render()`, which finds elements by id and builds the table of `<input>` cells. It sets no globals.
- Picker buttons call `choose(level)`; `newPuzzle` resets state. Per-cell `keydown`/`input` handlers call `nextCell`, `applyEntry`, `sanitizeDigit`.
- Value change (`setCell`, the single write path): `before` grid -> `creditEntry`; then `clearResults`, `showClashes(after)`, `fixedMessage`, the credit text, then `completionFor` (wins when the grid is full), else `showRewardMarks(credit.marks)` when marks are set (#122: Hint mark classes `hint-area`/`hint-confined`/`hint-removed` + `data-d`, key into `keyText`, then `unlink()` writes it to the reserve; no rings, hatching, target or links; `clearResults` removes them like a hint); `showTally`.
- `clearResults` (Verify, Hint, value changes, `choose`, `newPuzzle`) clears the status, the step-reveal state `steps` and the Next step row (#90), `keyText`, `hatchedRings` and the reserve/invitation (`unlink`), red flags and all hint classes (including `hint-hatched`)/`data-d`; never `td.clash`. Notes changes do not call it, so a hint and its key line survive them.
- `showMarks(marks, stage)` (add-only, #91): stage 1 target/area/confined + `data-d`, 2 + removed, 3 + hatched, rings and `hatchedRings` (so links are inert before 3); sets `keyText` via `hintKey(..., stage)` (shown in the `#link` reserve). Hint calls it with `steps ? 1 : 3` (`steps.marks` keeps the marks), `revealStep` with `steps.shown`.
- Hint button: `hintFor(grid, step, preferredTechnique(tally, currentLevel), currentLevel)`, `clearResults`, `hintMarks`; marks go through `showMarks`. The key (`hintKey`) shows on every explain except a naked single; when hatched cells show (stage 3), `hatchedRings = {hatched, rings: marks.digits, d}` (d = pointDigit for pointing, else digit) and `showInvite()` (after the focus call, also in `revealStep`) fills `#key` and calls `scrollIntoView({block: 'nearest'})` once (#97). While `steps` is set, Hint only calls `revealStep` (until step 3) and focuses the target, no redraw (#90); `revealStep` (also the Next step button) focuses the target at step 3. `cellAt(q)` is shared inside `render`.
- Link (#68, #72): `unlink()` removes `hint-linked`, and `hint-ruled` with its `data-d` (#78), and restores the reserve to `keyText` (class `selected` off) and the invitation (empty when nothing is hatched); `showLink(text)` puts a link sentence in the reserve with class `selected`; `clearResults` calls it. `focusin` on the table calls `unlink()`, then: an entered ring -> `selectRing(p)` (adds `hint-linked` to the ring, `hint-ruled` plus `data-d` to `ringRules(...).cells`, shows its text); a hatched cell -> `hint-linked` on `ringLink(...).partners` and its text. `focusout` -> `unlink`. A document-level `click` handler (runs after the focusout of the cell that lost focus) ignores editable cells (left to focusin, else it would undo a forward link), otherwise unlinks and, on a given ring, calls `selectRing`; it returns early when no hint with hatching shows.
- `relabel(inp)` is the only aria-label builder (position, notes, ", clashes").

## ATDD (#110, it22; rules in process.md "Test strategy applied")
- `specs.test.js` loads every `steps/*.js` (each exports `(define) => {}`, `define(regex, fn)`) and calls `runner.register`: one `node:test` per scenario and per Examples row, read straight from `specs/**/*.feature` (executed, not translated).
- `gherkin.js` parses features; `runner.js` expands Examples, resolves steps and fails on: undefined step, ambiguous step (two regexes match), a placeholder without a column, a parse error, a feature with no scenarios, no feature files. `runner.test.js` self-checks the runner (9 cases).
- Step texts are global across features: a new steps file must not redefine an existing text. Reuse `the message reads "..."` etc. from `steps/own-singles.js`; `steps/hints.js` adds the hint steps.
- Steps hold the assertions; drivers hold no assertions. `drivers/game.js` is the only spec code that imports product modules (`hints.js`, `rewards.js`; logic level: `start(rows)`, `enter`, `hintTwice`, `lines`, `linesBeforeLastEntry`, `marksFor` reads `creditEntry(...).marks`, the product decides). `drivers/local-run.js` (#121, process level; steps in `steps/local-run.js`): `readmeSection(name)`, `runAndFetch(command)` (re-runs itself as a `--crawl` helper via `execFileSync` because steps are synchronous; starts the real `node tools/serve.js` on 127.0.0.1:8000, fetches the page and every file it loads with 5 s timeouts, kills the server also on SIGTERM/SIGINT; SIGKILL of the helper can still orphan it), package facts (package.json dependency fields, static and dynamic `import()` specifiers). Step files: `own-singles.js`, `hints.js`, `reward-marks.js`, `local-run.js`. "asks for a hint twice" = `hintFor` step 2 = the full explanation (PM D11); there is no page driver yet.
- Known limits (PM D6): an unused Examples column passes silently (PM rule: every column is used); no `|` inside cells.

## Tests
- Run `node --test` from the repo root (on Node 24 `node --test tests/` and `node --test spec-implementation/` fail: give no path, or a file); it runs `tests/` and the specs. 230 tests (21 spec scenarios), about 6 s with Chrome. Specs only: `node --test spec-implementation/specs.test.js`. 127.0.0.1:8000 must be free (the ADR 002 spec runs the server there; a busy port fails in about 140 ms with "port 8000 is already in use"; a 0.0.0.0:8000 listener does not clash). Scratch servers use other ports (testers used 8101/8102, 8111/8112).
- Page tests (#55, #116): `tests/page.test.js` serves the repo with `serve(0)` from `tools/serve.js` (random free port) and loads `index.html` over http in one headless Chrome; `Math.random` is seeded by `window.__seed(n)`, which imports `/generation.js` and installs `seededRng(n)` (no source extraction, no test hooks or globals in product code); keydown on cell inputs and real button clicks; DOM-only reads. Chrome via `CHROME_PATH` or default macOS/Linux paths; `WEAVER_NO_CHROME=1` or a missing Chrome gives a visible skip with a reason (page evidence must show skipped = 0). Cleanup on normal end, failure, Ctrl-C/SIGTERM and the orphaned test child (EPIPE listeners, ppid watchdog); not after `kill -9`.
- Do not serve the page with `python3 -m http.server`: its listen queue resets Chrome's parallel module requests (3 of 6 loads failed, #117). Scratch scripts use `tools/serve.js` (`serve(port)`).
- Narrow-width page checks use `Emulation.setDeviceMetricsOverride` (headless Chrome's window has a ~500 px minimum), wait for layout to settle (check the cell width), and clear the override in `finally`.
- Seeds are chosen on purpose: a seeded test guards a rule only if one of its seeds fails under the mutant.
- Which page test pins what (f, f1-f1h, f2, f4, f5, g1, r1): `page-tests.md`. Read it only when adding or changing a page test.
