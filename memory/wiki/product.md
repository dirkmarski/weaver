# Product: what weaver is today

A dependency-free static page (open `index.html`, no build) that generates a fresh sudoku at run time, with exactly one solution, and teaches solving techniques. Strategy (`governance/context/product-strategy.md`): educate the user, teach techniques progressively, reward learning and applying skills; solving is secondary.
Authoritative behaviour spec: `README.md`.

## Features
- Level picker on load (Easy, Medium, Tricky, Tough, Hard; wraps 3+2 at 360/375 px, one line at 1280); puzzle generated only after choosing. "New puzzle" returns to the picker.
- 9x9 grid, 3x3 boxes shaded in two alternating light colours. Givens bold and locked.
- Digits 1-9 typed (or pasted/dropped as one digit); other input rejected. Backspace/Delete clears (Notes off).
- Pencil-mark Notes (button or `N` key, starts Off each puzzle); notes ignored by Verify and Hint.
- Keyboard: arrow keys jump to the nearest non-given cell in that direction, no wrapping.
- Verify: rules-only check (no stored answer), shows the player's repeated digits in red (givens never red), counts empty cells.
- Clash outline (#51, it11): every clashing cell, givens included, gets a dashed orange outline (`td.clash`) while the clash lasts. It is recomputed on every value change only; Verify, Hint, notes and arrow keys never touch it, and New puzzle or a level choice clears it. Editable outlined cells end their aria-label with ", clashes". This is the only live mark: red stays Verify-only.
- Clash fixed (#51): a value change (clear or overwrite) that goes from at least one clash to none shows "No numbers break the rules now. New entries are counted again." (plain); completion wins if the grid fills.
- Auto message when the grid is full: green "Puzzle solved! Techniques applied: O on your own, H with a hint." (sums of all four techniques) or red pointer to Verify on a conflict.
- Nothing is stored between page loads.

## Levels
| Level | Givens | Needs |
|---|---|---|
| Easy | 36-40 | naked singles only |
| Medium | 30-35 | hidden singles as well; not solvable by naked singles alone |
| Tricky | 27-31 | pointing as well; following Hint solves it; not solvable by singles alone |
| Tough (#103, it21) | 27-31 | as Tricky (same generation and grading); Hint prefers a useful claiming step |
| Hard | 22-29 | unique solution; not solvable by singles plus pointing |

- Grading discards a puzzle that the lower level's technique already solves. Generation is a few ms (Tricky tens of ms, up to a few hundred); a 1000 ms cap returns the best unique puzzle found with `capped: true`.
- Tricky bands overlap Hard at 27-29 givens; givens are not shown to players (accepted, it8).
- A level that needs claiming is not generable in time (it21 spike: 47-54 of 60 capped), so Tough practises claiming through Hint: p10/p50/p90 2/5/8 claiming lessons per puzzle (pointing 0/2/4), never stuck (seeds 1-100). Grading (`solvableBy`) is still pointing-only: Hard is "not solvable by singles plus pointing", claiming is not considered. Personas do not feel Tough as harder than Tricky and want the picker to say what it is (#103).
- Tricky puzzles mostly need one pointing step to solve, but Hint prefers useful pointing there (#60): a player who follows Hint gets 2/4/6 pointing lessons per puzzle (p10/p50/p90, seeds 1-300), the first at about entry 5. Personas rated that load "about right" (it13).

## Techniques taught
- Naked single: an empty cell where row, column and box leave one digit.
- Hidden single: a digit with one possible cell in a box, row or column.
- Pointing: a digit confined to one row/column within a box cannot go elsewhere in that line; this can create a single. On Easy, Medium and Hard taught only when no single exists; on Tricky and Tough a useful pointing step comes first (#60).
- Claiming (box-line reduction, #102-#104, it21): in a row or column L, digit D fits only in cells inside one box B, so D is struck from B's other cells; this can create a single. Taught on every level as a fallback after pointing; on Tough a useful claiming step comes first of all. Definition line: "In a row (or column), a digit fits only inside one box, so it cannot go anywhere else in that box (pointing in reverse); that can leave a single."

## Hint
- Never fills a cell. Two clicks: first a nudge (target cell amber and focused, area tinted), then an explanation (digit named, marks added).
- Pointing nudge says what the step does (#45): naked form "That means D cannot go in row R, column C, and only one other digit fits there now."; hidden form "Then look at U: D now has only one place left there." The hidden-form unit is tinted on both clicks.
- Pointing explanation, naked form (#71): "... Row R, column C has every digit except D and X in its row, column and box, so it could only take D or X. With D now ruled out there, it must be X." (the clause held in 77/77 and 132/132 checked cases). Hidden form: "That leaves row R, column C as the only cell in its U where D fits, so it must be D." Step 2 (#96, it20) names every struck cell: "2. So D cannot go in row L outside that box: not in <cells> (struck)." with <cells> = "row R, column C" for one cell, else the line first, ascending, "and" before the last ("row 1, columns 5 and 6"; "column 3, rows 4 and 6"); personas "text matches the struck cells" 5/5/5. Since #77 the pointing explanation is four lines: a conclusion line, then three numbered steps (the box note at the end of step 1), shown as a left-aligned block (`#status.steps`: pre-line, max 36rem) below the buttons; every other message stays centred. Step by step (#90, it19): the second click shows the conclusion and step 1 plus a "Next step (2 of 3)" button (play-button size, own `<p id="next">` under `#status`); the button or Hint adds the next step (cumulative); after step 3 the button goes, focus returns to the target cell, and further Hint clicks change nothing. Clearing paths remove it; notes keep it. Personas: learning 4/4/4, button ease 4/4/4. Staged marks (#91, it19, staging P): step 1 = target, tint, confined (key "Key: dashed purple = the only places for D in the box."); step 2 + struck removed badges (key adds the struck clause); step 3 + hatching, rings, link invitation, today's full key; hatched/ring links react only from step 3. Personas "marks match the step" 4/4/4; staging Q (rings at step 1) not wanted 2/3.
- Rings (second click, #56): a cell holding the key digit D gets a purple ring only if it rules out a "reason cell" (shares a row, column or box with it). Hidden single: the other empty cells of its unit. Pointing: the empty box cells that are not confined, plus in the hidden form the empty cells of U other than the target and removed cells. All qualifying rings are kept (PM D4); there may be none. Naked single: no rings.
- Pointing explanation also marks confined box cells (dashed purple outline, purple D badge) and removed line cells (grey struck D badge, also on the target). The badge sits in D's own pencil-note slot (1 top-left ... 9 bottom-right); below 560 px its side padding is 1 px and edge badges sit flush inside the cell (touching a neighbour note by about 1 px at most at 375 px). 320 px is out of scope. The struck badge's diagonal band (#61) is #6b6b6b (5.3:1 on white), 43-57% of the chip's corner-to-corner gradient: at least 2.27 px at 375 px and 2.91 px at 1280 px; the chip width follows the glyph, so D = 1 is the thinnest.
- Hatching (#65, it14): on the second click of a hidden single or pointing step, the reason cells (the empty cells the rings rule D out of) get purple diagonal stripes (135deg, #6a1fb5 at 0.25 since #68, 1.5 px every 8 px) on top of the amber tint; notes and values paint above. Hatching shows exactly when rings show (PM spike, 1855 explanations). None on the first click or for a naked single.
- Key line (#56, reworded #65, moved by #97 it20): in the 4-line reserve under the board (`#link`), plain grey (#444, 400) and smaller, during a pointing or hidden-single explanation. Pointing: "Key: dashed purple = the only places for D in the box; struck grey D = this step rules D out there; hatched = a purple ring rules D out there (A already in the same row, column or box)." (the hatched clause is dropped when nothing is hatched). Hidden single: "Key: hatched = a purple ring rules D out there (A already in the same row, column or box)." (always shows: a hidden single always has a hatched cell). A is "a D" / "an 8". No form, unit or count variants. None for a naked single, a nudge or other texts. While a hatched cell or ring is selected, the link sentence replaces it in the reserve (purple, 500); deselecting restores the key. Personas "find the key" 4/4/4 (#97, no margin over the 4.0 target).
- Box case (#56): when every empty box cell is confined, the explanation inserts " (the box has no other empty cells)" after "fits only in row/column L".
- Claiming hint (#102): mirrors pointing (same nudge, 3-step reveal, staged marks, key, rings, links), line -> box. Nudge "Hint: try claiming. In L, the digit D fits only in the box of rows R1-R2 and columns C1-C2, so it cannot go anywhere else in that box. ..."; steps "1. In L, the digit D fits only in <box>.", "2. So D cannot go anywhere else in that box: not in <cells> (struck)." (cells not in one line are grouped per row, joined by "; ", D3), step 3 as pointing but the hidden form names its unit ("the only cell in column 4", D4; pointing still says "its U"). Key "dashed purple = the only places for D in the row/column". Search order rows 1-9, then columns 1-9, digits 1-9. Exact texts: README "Claiming". Personas: understand 4.33, marks 4.78 (#102); learn on Tough 4.0, picker 4.0 (#103, at the threshold).
- Priority: conflicts first (#50: names the clash, plain style: "Row R1, column C1 and row R2, column C2 both hold E in the same U. Change or clear one of them first, then click Hint again." plus " Other numbers break the rules too: click Verify to see which." when more than two cells clash), full grid message, then (Tough only) a useful claiming step, then (Tricky and Tough, #60) a useful pointing step, i.e. one whose target is not already a naked or hidden single, then singles, then pointing, then claiming, else "No naked single, hidden single, pointing or claiming step right now..."
- Single preference: teaches the technique with the lower own-plus-hint count; on a tie naked on Easy, hidden on Medium/Tricky/Hard. A preferred hidden single is one that is not also a naked single.
- Pointing target: boxes in reading order, digits 1-9, first step that creates a single; naked and hidden forms are mutually exclusive. The Tricky useful step skips targets that are already singles and passes over a step with no other target (`findPointing(grid, {useful: true})`).
- Invitation and link sentences, forward and reverse (#68 it15, #71/#72 it16; layout #97 it20): while an explanation with hatched cells shows, a purple invitation line (`#key`, #4a0f8a, 0.85rem, weight 500) under `#status` and the Next step button invites "Click or tap a hatched cell to see what rules it out (solid purple), or a ring to see which cells it rules out." When it first appears (Hint or Next step, after the target is focused) the page scrolls it into view with the minimum scroll (`block: nearest`, 1 px scroll margin); selections never scroll. The link sentences below show in the reserve under the board (key line above), so the button row never moves. Forward: while a hatched cell has focus (click, tap, arrows), its partner rings (1 or 2 ringed cells sharing a unit with it) take the linked look (`hint-linked`: solid #6a1fb5, white digit, #4a0f8a inner ring) and the line reads e.g. "Hatched cell row 2, column 3: no 5 here, because the 5 at row 2, column 8 is in the same row, and the 5 at row 9, column 3 is in the same column." (D = the hint's digit; for pointing the pointing digit). Reverse (#72): a click/tap on a ring (given or entered) or focus on an entered ring selects it: the ring takes the linked look, the hatched cells it rules out (1-4; exactly the reverse of the partners) get the ruled look (`hint-ruled`, #78: a purple struck D badge in D's note slot, #4a0f8a digit, band and 1 px border on a white chip, 12.16:1; it covers the player's own D note while selected; stripes and tint stay) and the line reads e.g. "The 4 at row 4, column 6 rules 4 out of two hatched cells: row 4, column 4 (same row and box) and row 6, column 4 (same box)." (words one-four; numeral above four, never seen). Re-clicking keeps the selection; another ring switches; a hatched cell shows the forward link instead; focus/click on any other cell, a non-ring given or outside the grid reverts (the key line returns to the reserve). Forward and reverse never show together. Givens remain unfocusable (no keyboard reach to given rings).
- Entering the hinted digit shows "Well done! You applied ...". Any change to a value, Verify, New puzzle or a level choice removes the hint, its hatching, its key line, the link line and linked rings; notes changes keep them.

## Rewards and counts
- Entering a digit (Notes off) into an empty cell is judged: naked single, else hidden single (box, row, column checked in that order), else pointing on your own, else claiming on your own (#104; ONE step makes the entered digit a single in that cell, naked or hidden form; chained steps are not recognised), else a neutral "not counted" message. Order of the "not counted" texts (#50, it11): (1) the digit is already in the cell's row, column or box: "D is already in this cell's U, at row R2, column C2, so it breaks the rules. It is not counted." (first unit of row/column/box, first holder in reading order); else (2) the grid before the entry already breaks the rules: "D is not in this cell's row, column or box, but <named clash>, so it is not counted. Change or clear one of them first. Entries after that count again; this one stays uncounted." (+ the extra sentence when more than two cells clash); else (3) "It was not a naked single, a hidden single, a pointing step or a claiming step...". Entries during a clash are never counted later.
- Named clash (`namedClash`, #50): P = first clashing cell in reading order (givens included), E its digit; partner Q = first other holder of E in P's row, else column, else box; phrased "row R1, column C1 and row R2, column C2 both hold E in the same U".
- "Well spotted!" for own finds (own pointing names the step: "...in the box of rows R1-R2 and columns C1-C2, the digit D fits only in row L, so row R, column C is V."; own claiming: "...in row L, the digit D fits only in the box of rows R1-R2 and columns C1-C2, so row R, column C is V."), "Well done!" for hinted ones. Hinted pointing and claiming are counted too. Both own messages skip the final step (why the cell is V): persona gate 3.5 < 4.0 at #104, waived by PM D16; #108 (it22 item 1) adds the final step as hinted step 3 does.
- Block under the status shows four lines, Naked single, Hidden single, Pointing and Claiming ("N on your own, M with a hint"), each with a grey definition, on every level, always visible. At 360/375 px the lower lines (Claiming) sit below the fold (#104 tester F4, mobile backlog).
- Status colour comes from `creditEntry`'s `kind` (reward = green, "not counted" = neutral).
- Each cell counts once per puzzle; counts never go down; reset on choosing a level.
