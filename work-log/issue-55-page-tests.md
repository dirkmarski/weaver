### Rework round 2
- L3 causes found by tracing the test child (heartbeat plus signal/exit log): `node --test` handles SIGTERM/SIGINT by exiting itself and does not wait for its test child. The child is orphaned (ppid 1), keeps running, and when it next writes results to the dead pipe it throws EPIPE; printing that to the dead stderr kills it silently, so no handler and no `exit` event runs (traced: no `got SIGTERM`, no `exit`). Depending on timing (signal around 1.0-1.3 s, while results stream) the child got its SIGTERM first (clean) or died of EPIPE (Chrome left running, profile left). Secondary: the sync rm right after SIGKILL could race a dying Chrome; `process.once` allowed a second signal to take the default action. Direct `node tests/page.test.js` plus SIGTERM was always clean, which isolated the runner.
- Change (`tests/chrome.js` 79 -> 100 lines; `tests/page.test.js` 1 line: `after` returns the promise): `close()` is now async and idempotent: kill the Chrome group, wait for the Chrome `exit` event (2 s bound), then `rmSync` (maxRetries 5), then profile is gone. Signals use `process.on` and share that one promise, then `process.exit(130/143)`, so repeated signals are harmless. Orphan detection: `error` listeners on stdout/stderr (EPIPE) and a 200 ms unref'd `process.ppid` watchdog both run the SIGTERM path. The sync `process.on('exit')` fallback stays (kills the group, waits up to 100 ms unless Chrome is already reaped, rm with retries). Launch failure awaits `close()`. README: "(not after `kill -9`)".
- Not fixable from the harness: SIGKILL of the test child (or of the whole runner and child) runs no JS, so a Chrome group and profile can remain. The runner sends its own signal-driven kill, not SIGKILL, in the traces.
